# Учебные упражнения

Выполняйте в demo-стенде. Перед началом `make demo`, затем сохраните counts.

1. **Повторная доставка.** Повторите `make demo`. Ожидание: 3 строки ODS, итоговый
   счёт первого матча 4:0, нет увеличения processed_count от повторов одного event_id.
2. **Независимый consumer.** Уменьшите replicas consumer до 0, запустите DAG.
   Publish завершится, verify получит timeout, Kafka lag вырастет. Верните replicas=1;
   дождитесь completed и lag=0. Повторите verify в Airflow.
3. **Позднее событие.** Опубликуйте revision=1 после revision=2 через demo_check
   либо интеграционный тест. Итоговый счёт остаётся 4:0.
4. **DLQ.** В одноразовом тестовом Kafka отправьте некорректный JSON. Проверьте
   DLQ и отсутствие изменений ODS. Затем используйте тест
   `test_snapshot_accounting_rejection_replay_and_repair` для восстановления.
5. **Простой VM.** Запишите последний период, выключите учебную VM, затем после
   запуска выполните backfill явного периода. Не ожидайте автоматического catchup.
6. **Восстановление.** Включите backup для demo отдельным values override, выполните
   `make backup`, дождитесь Job Complete и запустите `make restore-check`.
   Исходная DWH остаётся неизменной; временная БД удаляется после проверки.

Для отчёта сохраните команды, ожидаемый и фактический результат, lag до/после,
время восстановления. Не ограничивайтесь скриншотом зелёного DAG.
